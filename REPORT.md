# Отчёт по бонусному заданию

**Проект:** Email Ban Checker  
**Задание:** создать форму на HTML и JavaScript для проверки email по массиву заблокированных адресов.  
**ИИ-инструмент:** OpenAI Codex.  
**Количество итераций:** 1. Прототип создан и проверен по одному запросу пользователя.

## Результат

Форма проверяет формат адреса, ищет его в локальном списке без учёта регистра и пробелов по краям и показывает результат на странице. При изменении адреса предыдущий результат исчезает.

## Проверка

Тесты выполнены в Microsoft Edge на локальной странице.

| Ввод | Фактический результат |
| --- | --- |
| `spam@example.com` | Заблокирован |
| `SPAM@EXAMPLE.COM` | Заблокирован |
| ` blocked@example.com ` | Заблокирован |
| `user@example.com` | Отсутствует в списке |
| Пустая строка | Просьба ввести email |
| `invalid-email` | Сообщение об ошибке формата |

Дополнительно проверены отправка клавишей Enter, очистка результата после изменения адреса, отсутствие перезагрузки при проверке и вёрстка при ширине окна 320 px.

## 4. Функциональность приложения

Создай веб-страницу со следующими элементами:

1. Заголовок: **Email Ban Checker**.
2. Краткое описание: «Проверка email-адреса по списку заблокированных пользователей».
3. Поле ввода email.
4. Кнопка «Проверить».
5. Область для вывода результата.

### Логика

В `script.js` создай массив строк с тестовыми заблокированными адресами:

```javascript
const bannedEmails = [
  "spam@example.com",
  "blocked@example.com",
  "testban@example.org"
];
```

При вводе адреса и нажатии кнопки приложение должно проверять его наличие в массиве.

**Если email найден:**

Показать сообщение:

«Доступ запрещён: email находится в списке заблокированных».

**Если email не найден:**

Показать сообщение:

«Email не найден в списке заблокированных».

### Дополнительные условия

- Удалять пробелы в начале и конце введённого адреса.
- Сравнивать email без учёта регистра.
- Проверять корректность формата email.
- Не допускать проверки пустой строки.
- Поддерживать отправку формы нажатием Enter.
- После изменения адреса предыдущий результат не должен вводить пользователя в заблуждение.
- Не перезагружать страницу при проверке.
- Не использовать `alert()` – результат должен отображаться непосредственно на странице.

Реализуй проверку через обычный JavaScript без сервера.

Не нужно создавать базу данных, регистрацию пользователей или авторизацию.

Это исключительно демонстрационный прототип.

Вынеси стили в отдельный файл `style.css`.

### JavaScript

Вынеси логику в отдельный файл `script.js`.

Код должен быть простым, читаемым и снабжён короткими комментариями там, где они действительно полезны.

Не используй `eval()`, динамическое выполнение кода или потенциально опасную вставку пользовательского HTML.

Учти, что список заблокированных адресов расположен в клиентском JavaScript и предназначен только для демонстрации. Это не полноценный механизм серверного контроля доступа.
